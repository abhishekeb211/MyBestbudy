## Review pass 0 — Baseline from the two uploads

**Source description:** The original concept proposes Move → Pause → Think → Connect → Reflect, a map/character progression system, brief scenarios, a phone-break game, optional CBT/REBT-like exercises, social challenge, and inferred psychological patterns from choices, reaction times, steps and responses. The checklist adds UI screens, 25 criteria, 5 narrative zones, timers, skill trees, privacy and safety, and phased delivery.

**Audit finding:** These materials do not include the detailed list of 25 criteria, reference UI images, code, performance measurements, independent test datasets, or completed safety evaluations. Therefore, existing implementation and accuracy claims are not independently checkable.

**Correction:** Every proposed feature starts as `ADOPTED_DESIGN`, `DEFERRED` or `OPEN`, never `VALIDATED`. Checkpoints below are design reviews, not completed user tests.

## Review pass 1 — Make the product claim precise

### D-001 — Change from psychological profiling to everyday-skill practice

- **Old proposal:** Quietly infer mental-health patterns or hidden criteria from ordinary game interactions.
- **Status:** `ADOPTED_DESIGN` for direct skill practice; hidden inference `REJECTED`.
- **Decision:** Teach focus routines, evidence checking, planning and alternative thinking. Do not infer anxiety, depression, withdrawal, personality or another clinical state.
- **Why:** Interaction signals are confounded, reference outcomes are missing, and hidden assessment conflicts with privacy and trust. Direct educational objectives are more transparent.
- **Unproven assumption:** Brief practice can produce useful learning.
- **Validation:** Independent *unseen* skill items plus real-life behavioral measures against an active control.
- **If wrong:** Remove or rewrite ineffective content and narrow promotional claims; never invent a clinical score.
- **Affected sections:** 0, 1, 2.3, 4, 8 of project document.

### D-002 — Separate improvement at game tasks from general mental ability

- **Old proposal:** More correct answers/retention implicitly proves mental improvement.
- **Status:** `ADOPTED_DESIGN`.
- **Decision:** Three distinct outcomes: usability, untrained skill performance, and practical real-world transfer.
- **Why:** 2016 meta-analysis found no convincing broad far-transfer improvements from working-memory training compared with active controls; 2026 research reports some small/direction-specific effects, reinforcing uncertainty rather than an IQ claim.
- **Evidence:** https://pubmed.ncbi.nlm.nih.gov/27474138/ ; https://doi.org/10.3758/s13423-026-02994-5
- **Unproven assumption:** QuestMind activities provide meaningful practice beyond familiar game prompts.
- **Validation:** Randomized active-control study with independent preregistered outcomes.
- **If wrong:** Say "better at QuestMind exercises," not "better intelligence"; pivot to an enjoyable habit tool.

### D-003 — Use a small, understandable daily loop

- **Old proposal:** Run all five modules and every psychological layer inside each day.
- **Status:** `ADOPTED_DESIGN`.
- **Decision:** One main quest per day; 60–90 seconds of active interface time; offline activity can take longer; optional modules remain optional.
- **Why:** The original idea's strongest feature is low burden, not maximal feature density.
- **Unproven assumption:** Short interactions support repeatable voluntary use.
- **Validation:** Usability sessions measuring task completion time, comprehension and drop-off; separately measure time away from app.
- **If wrong:** Reduce to one action and one feedback screen; allow longer user-selected lessons only.

## Review pass 2 — Rebuild each module safely

### D-004 — Make MOVE inclusive rather than step-gated

- **Old proposal:** Steps are the engine and progression currency; often add 1,000–2,000 steps.
- **Status:** `ADOPTED_DESIGN` with changes.
- **Decision:** Walking is one option, alongside safe alternative movements. No universal step quota; sensor permissions optional.
- **Why:** Movement has supportive cognitive research, but fixed quotas exclude some users and step counts do not reveal mental state.
- **Evidence:** 2025 exercise umbrella review, https://doi.org/10.1136/bjsports-2024-108589
- **Unproven assumption:** A choice of accessible movement activities will be engaging.
- **Validation:** Permission-denied and mobility-accessibility tests, discomfort reporting, optional real-world activity outcomes.
- **If wrong:** Turn movement into a purely optional prompt with no exclusive rewards.

### D-005 — Be honest about PAUSE verification

- **Old proposal:** Users earn credit for not touching the phone, with implied certainty.
- **Status:** `ADOPTED_DESIGN`.
- **Decision:** By default credit is explicitly **self-reported**. Only label as device-verified when a suitably permissioned, technically supported metric measures the claimed behavior.
- **Why:** Pressing a timer is not proof the phone went unused; unrestricted app monitoring is unnecessary.
- **Unproven assumption:** Voluntary phone breaks are motivating even without exhaustive tracking.
- **Validation:** Study how users understand labels; verify OS permission handling, false positives and opt-out.
- **If wrong:** Remove device measurement, retain transparent self-report, or simplify to intention-setting only.

### D-006 — THINK teaches one skill; not a personality probe

- **Old proposal:** Every Drop maps onto multiple latent psychological criteria; use fast answers as signals.
- **Status:** `ADOPTED_DESIGN` for skills; latent mapping `REJECTED`.
- **Decision:** Each Drop has a named learning goal, clear explanation, and optional nonjudgmental alternative.
- **Why:** Teaching 2–3 hidden constructs at once weakens both educational clarity and measurement validity.
- **Unproven assumption:** Users can learn the concept from a short example.
- **Validation:** Novel equivalent-but-unseen examples, comprehension interviews and accessibility review.
- **If wrong:** Use a better explanation or slightly longer practice; abandon the content if it remains confusing.

### D-007 — Make CONNECT supportive, not rejection-seeking

- **Old proposal:** "Collect the No" social challenges give double points for rejection.
- **Status:** `REJECTED` original; safe alternative `DEFERRED` to later phase.
- **Decision:** Optional appreciation, asking for assistance from a trusted contact, or solo perspective-taking.
- **Why:** Incentivizing rejection may pressure vulnerable users or involve others without consent.
- **Unproven assumption:** Safe social action creates enough benefit to justify additional complexity.
- **Validation:** Small opt-in usability/safety study with no social graph collection.
- **If wrong:** Keep the app fully solo.

### D-008 — REFLECT is feedback, not inferred wellbeing

- **Old proposal:** "Called out / needed this / nah" is the highest-value hidden psychological signal.
- **Status:** `ADOPTED_DESIGN` with change.
- **Decision:** "Useful / Not useful / Skip" expresses content preference only; personal reflection is optional and local.
- **Why:** Feeling understood by a sentence does not independently measure psychological state or content correctness.
- **Unproven assumption:** Optional feedback improves content recommendations without privacy cost.
- **Validation:** Compare with no-feedback default on relevance and burden.
- **If wrong:** Stop collecting reactions entirely.

### D-009 — Remove mandatory 10-second psychological countdowns

- **Old proposal:** User must commit rapidly; last-second selections infer hesitation.
- **Status:** `REJECTED` mandatory countdown and covert inference.
- **Decision:** No pressure timer on personal reflection. Optional timers only for clearly recreational, harmless tasks, with accessibility bypass.
- **Why:** Reading speed, disability, language and device lag confound reaction time; pressure can degrade comprehension.
- **Unproven assumption:** Relaxed choice still feels engaging.
- **Validation:** A/B compare optional timer versus no timer on comprehension and discomfort; record only necessary aggregate UX data, not hidden traits.
- **If wrong:** Add user-controlled novelty or graphics, not mandatory timed introspection.

### D-010 — Keep cumulative progress and healthy exit

- **Old proposal:** Particle map never empties, no streak penalty, graduation when app is needed less.
- **Status:** `ADOPTED_DESIGN`.
- **Decision:** Keep this; do not add loss-framed streaks, scarcity loot boxes, shame notifications or forced daily return.
- **Why:** Retention is not the ultimate success measure for an off-screen habits app.
- **Unproven assumption:** Visible cumulative progress is motivating without compulsion.
- **Validation:** Perceived autonomy, pressure and unprompted engagement; independent behavior improvements.
- **If wrong:** Reduce visual rewards, make progress view optional.

## Review pass 3 — Technology and user privacy

### D-011 — Local-first; data collection not necessary for basic play

- **Old proposal:** Monitor phone behavior, mobility/location, social behavior and responses to infer states.
- **Status:** `ADOPTED_DESIGN` for local-first; collection of broad sensitive streams `REJECTED` for MVP.
- **Decision:** No sign-in, analytics SDK, precise location, contacts or microphone required for MVP. Optional steps and screen usage with granular consent; consented research data separate.
- **Why:** Unnecessary data expands failure modes without proving benefit.
- **Evidence:** NIST Privacy Framework, https://www.nist.gov/privacy-framework
- **Unproven assumption:** Most core value can be delivered offline.
- **Validation:** Airplane-mode test, permission-denied tests, app data inspection, deletion/export tests, threat model.
- **If wrong:** Justify minimum additional data field and purpose publicly, review risk, then retest; otherwise remove the feature.

### D-012 — Rules first; agentic AI behind review gates

- **Old proposal:** Implicit adaptive psychological engine, potentially AI-driven.
- **Status:** `ADOPTED_DESIGN` rules; real-time agentic AI `DEFERRED`.
- **Decision:** Ship a deterministic quest selector and reviewed content. Use agents in development only to propose content, check sources, run safety adversarial reviews and inspect privacy; humans approve.
- **Why:** No evidence yet that a runtime model is necessary; unbounded generated personal reframes add avoidable uncertainty and data risk.
- **Unproven assumption:** Simple rules are sufficiently engaging and useful.
- **Validation:** Compare rules with static catalog; consider model only with measured improvement and explicit new controls.
- **If wrong:** Incrementally test bounded local AI offline with new safety and privacy reviews; maintain a no-AI fallback.

### D-013 — Protect all users without country-specific product logic

- **Old proposal:** Legal concern framed around one location and age group.
- **Status:** `ADOPTED_DESIGN`.
- **Decision:** Privacy, accessibility, truthful claims and data controls apply to everyone. Adult pilot scope is pragmatic research sequencing, not an assertion that younger users do not matter. No country-specific rule is included in the core design.
- **Why:** Data minimization and user autonomy are broadly applicable engineering objectives.
- **Unproven assumption:** One clear base design can serve diverse users with localized content.
- **Validation:** Inclusive usability studies, permissions/data-flow audits and later age-specific evaluation.
- **If wrong:** Provide age-appropriate localized modules and controls; do not weaken privacy for any group.

## Review pass 4 — Non-medical safety and accurate claims

### D-014 — Non-medical does not mean zero safety obligations

- **Old proposal:** Treat high-risk experiences as a separate crisis system and imply human escalation may be available.
- **Status:** `ADOPTED_DESIGN` safety path; unstaffed human-response promises `REJECTED`.
- **Decision:** No clinical predictions, no sensitive challenges; provide a clearly labeled Help path and truthful support resource information. No claim of monitoring or an emergency response service without staffing and operational evidence.
- **Why:** A general life-skills app can still encounter distress, but cannot improvise medical or crisis expertise.
- **Unproven assumption:** A bounded support information design is sufficient for the narrow MVP content.
- **Validation:** Reviewed content, scripted explicit-distress tests, human safety sign-off before pilots.
- **If wrong:** Restrict/free-text functionality, strengthen reviewed content, pause release.

### D-015 — Correct the old checklist's sequencing

- **Old proposal:** Build advanced modules before completing full safety review.
- **Status:** `ADOPTED_DESIGN` revised sequencing.
- **Decision:** Scope → privacy/safety → UI test → offline MVP → feasibility → controlled evaluation → optional expansion.
- **Why:** Late safety work creates expensive rework and exposes users prematurely.
- **Validation:** Every release gate shows real artifacts, not unchecked promises.
- **If wrong:** Stop the relevant pilot/feature; resolve the missing gate before continuation.

## Review pass 5 — Evaluation, incentives and scope control

### D-016 — Drop unverifiable percentage accuracy targets

- **Old proposal:** Claim quantitative psychological detection and improved accuracy from signal convergence.
- **Status:** `REJECTED` claims; measured evaluation `ADOPTED_DESIGN`.
- **Decision:** Do not publish percent improvement, diagnostic accuracy or confidence for QuestMind until real data and defined estimands exist.
- **Why:** Literature effect sizes come from *other* interventions and cannot be treated as project predictions.
- **Unproven assumption:** New implementation outperforms a simpler alternative.
- **Validation:** Comparative protocol with active control, predeclared primary outcome, sample size, uncertainty, adverse effects and external confirmation where appropriate.
- **If wrong:** Reduce scope, change framing to entertainment/skill practice, or stop underperforming feature.

### D-017 — Keep DAO-aligned transparency, reject health-token economics

- **Old proposal:** Add DAO-style incentives to the original project.
- **Status:** `DEFERRED` governance structure; tradable behavioral/health tokens `REJECTED`.
- **Decision:** Use off-chain participation, clear decision rights, reviewer approvals and non-transferable progress; no blockchain personal data.
- **Why:** A token economy is not necessary to validate daily skills and creates unnecessary incentive and privacy risks.
- **Unproven assumption:** Community input improves harmless UX choices.
- **Validation:** Governance process review after basic product feasibility.
- **If wrong:** Use conventional team governance without tokens or chain.

### D-018 — Define the minimal differentiator

- **Old proposal:** Five combined modules + hidden assessment + AI are presumed novel.
- **Status:** `ADOPTED_DESIGN` revised hypothesis.
- **Decision:** Test whether a very short, privacy-first, action-outside-the-app experience provides better outcomes or lower burden than a simpler self-guided alternative.
- **Why:** Feature combination is not automatically scientific novelty; comparative benefit is testable.
- **Unproven assumption:** The integration genuinely matters.
- **Validation:** Controlled ablation or active-control comparison, including burdens and costs.
- **If wrong:** Drop weak modules, leave one high-value minimal habit product.

## Change protocol — use after EVERY build, experiment, or challenge

1. **Identify:** assign `ISSUE-YYYYMMDD-NNN`; link affected `D-xxx` decision and files.
2. **Observe:** include actual data or reproducible steps; separate verified observations from complaints, interpretations and hypotheses.
3. **Assess:** privacy/safety severity, users affected, alternatives, and whether rollout must stop.
4. **Propose:** smallest reversible correction, reason, alternative rejected, data needed.
5. **Test:** prestate pass/fail metric and sample, run automated/usability/adversarial testing as appropriate; do not label a mockup result as an experiment.
6. **Decide:** owner + reviewer sign-off; `ACCEPT / REVISE / REJECT / ROLLBACK`.
7. **Record:** new entry appended; old entry marked `SUPERSEDED` only by an additional note; link code commit, experiment, version and checklist item.
8. **Recheck:** rerun dependent checks after changes; especially privacy, accessibility, safety and measurement validity.

### Example correction (HYPOTHETICAL ONLY; NOT A RESULT)

If prototype users report that the countdown makes a thinking prompt stressful, append a real entry with observed count, test conditions and affected population. A candidate fix would remove the timer, preserve a voluntary fast mode for simple non-sensitive games, then compare comprehension and comfort. Do not silently claim reduced distress without measuring it; do not erase the earlier decision.

## Snapshot: what changed in design version 3.0

**Retained:** Move / Pause / Think / Connect / Reflect; map progression; short scenarios; optional thought flexibility exercises; consent; no punishment for skipped days; off-screen action.

**Rebuilt:** optional/accessible movement, honesty about phone monitoring, direct skill learning, optional social action, useful/not-useful feedback, privacy-first local data, rules-first architecture, phased research, safety as a prerequisite.

**Removed from MVP:** covert 25-trait psychological profiling, using hesitations as a personality signal, mandatory 10-second psychological timers, rejection-as-currency, unvalidated clinical interpretations, claims of accuracy or broad intelligence improvement, mandatory cloud data collection, fake human crisis escalation, token incentives tied to sensitive disclosures.

**Next action:** run Phase 0 review with named owners. No future log entry should claim implementation, safety pass or improved learning without linked actual evidence.
